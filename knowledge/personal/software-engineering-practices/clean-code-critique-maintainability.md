# Clean Code Critique

**Summary:** Transcript critiquing standard "Clean Code" advice. It argues that code is read bottom-up when debugging, not top-down like a book and that excessive fragmentation (many small classes methods) makes navigation harder. It advocates for code isolation over mere aesthetic "cleanliness" (Internet of Bugs).

**Source:** ["Clean Code" Is Bad. What Makes Code "Maintainable"? Part 1](https://www.youtube.com/watch?v=8ncQrGuunHY) — Internet of Bugs.
